# 같은 원본 URL이어도 요청마다 새 번호를 준다

같은 원본 URL로 여러 번 요청해도 매번 새 연결을 만들어 새 번호를 준다. 이미 있는 연결을 찾아 돌려주려면 "찾기 → 없으면 저장" 사이에 동시 요청이 끼어드는 문제를 막아야 한다. 그러려면 원본 URL에 UNIQUE 제약을 걸고 충돌을 처리해야 한다. 또 `https://a.com`과 `https://a.com/`이 같은 주소인지도 정해야 한다. 새 번호 방식은 저장 한 번으로 끝나서 동시성 문제가 원래 생기지 않는다. 과제는 어느 방식이든 허용하고 README에 규칙을 적으라고만 한다.

## Considered Options

- **기존 번호를 돌려준다**: 같은 주소에 번호가 하나뿐이라 깔끔하고 DB가 덜 찬다. 하지만 동시 요청 처리와 "같은 주소"의 기준이 추가로 필요하다. 원본 URL은 입력한 그대로 저장하기로 해서, 그 기준도 애매해진다.
